# B1-M 技术特征增量实验设计

## 目标与边界

本轮属于 Phase M，只改变 B1-M 的输入特征。训练池固定为 CSI1000，训练期、valid/test
切分、默认标签、LGBM 超参、五个随机种子和 B1-S 策略全部保持不变。所有变体均以
`B1 v1.0` 为 `baseline_ref`，在 csi300/csi500/csi1000 三个测试池上用统一脚本评估。

## 预注册方案

方向统一为 `feature-technical`，一次性预注册四个变体，禁止根据 test 结果修改表达式：

1. `bollinger`：增加 20/60 日布林带位置、带宽、上下轨距离，以及价格上穿/下穿轨道
   和重新回到轨道内的事件特征。假设相对位置与稀疏穿越事件能补充 Alpha158 的
   `MA/STD` 原始分量，提高排序模型对超买、超卖及波动扩张状态的辨识。
2. `momentum`：增加 3 日短动量、5/20 与 10/30 跨周期动量差、5/20 日波动调整动量。
   假设跨周期差和风险调整后的方向强度比 Alpha158 已有单窗口 `ROC/SUMD` 更直接，
   可改善三池 RankIC。
3. `trend`：增加 5/20/60 日均线排列状态、20/60 日价格方向、20/60 日趋势效率、
   20/60 日斜率强度。假设显式的上行/下行/震荡代理能补充 Alpha158 的独立
   `MA/BETA/RSQR`，改善趋势状态切换时的排序稳定性。
4. `combined`：固定合并上述三组，不基于 test 做筛选。假设三个特征组具有互补信息，
   合并后 RankIC 与 RankICIR 的跨池表现优于任一单组。

## 实现

新增项目内 `Alpha158Technical` handler。它复用 `Alpha158` 的 158 个字段，并根据
`feature_groups` 参数追加命名稳定、无未来函数的 Qlib 表达式。配置只允许
`bollinger`、`momentum`、`trend` 三个组；未知名称、空列表和重复名称立即报错。
四个变体各生成五份 YAML，除 handler 类、模块与 `feature_groups` 外均复制 B1-M。

穿越事件只使用当日及历史值；训练标签仍为下一交易日收益。连续比率统一加
`1e-12` 防止零除。特征名在每个 handler 内唯一。

## 验证与报告

先用单元测试验证组选择、字段数量、名称唯一性、无负 Ref（未来数据）及配置冻结项；
再对每个变体运行 5 次训练，并用 `eval_ic_multi_pool.py` 一次评估三个测试池。报告
三池的 IC、ICIR、RankIC、RankICIR 和 CSI300 五种子配对胜负。无论改善或退化，均
登记 `registry.jsonl` 并由标准脚本重建 HTML；结论只描述相对数据，不提升基线。

实验收尾按显式白名单清理 `mlruns/`，只保留实盘模型和 B1-M 五种子产物。
