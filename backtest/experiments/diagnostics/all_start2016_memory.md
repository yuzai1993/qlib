# 全 A 2016 起点：内存观测

状态：`train-data/all-start2016` 已完成五个固定种子；2016 起点在当前 16GB M1
上可重复完成训练。

## 实验设置

`train-data/all-start2016` 的 handler 起点、fit 起点和 train 段起点为
`2016-01-02`，训练终点为 `2020-01-10`；使用 `instruments: all`、Alpha158
和冻结的 LGBM、valid/test、策略及费率设置。

实测按五种子串行执行；恢复运行的 seed 42 通过 `/usr/bin/time -l` 采集退出状态
与 maximum resident set size，未改变模型设置。

## 2026-07-24~2026-07-25 实测结果

五个固定种子均顺序完成训练、预测和回测。恢复后的 session 为：

| seed | session |
|---:|---|
| 42 | `20260724_231515_td_all_start2016_lgbm_s42` |
| 1000 | `20260724_232858_td_all_start2016_lgbm_s1000` |
| 2000 | `20260724_234044_td_all_start2016_lgbm_s2000` |
| 3000 | `20260724_235141_td_all_start2016_lgbm_s3000` |
| 4000 | `20260725_000231_td_all_start2016_lgbm_s4000` |

恢复运行的 seed 42 最大 RSS 为 6,329,368,576 bytes（约 5.89 GiB），0 swaps；
原始 `/usr/bin/time -l` 输出未单独落盘，因此这里将其视为运行时观测而非可独立
复核的原始日志。seed 42 全流程约 807 秒，其中：

- Loading data：约 259 秒；
- ProcessInf：约 117 秒；
- handler 全部初始化：约 555 秒；
- LightGBM 训练在 handler 初始化完成后正常结束。

其余四个恢复运行未用 `/usr/bin/time -l` 采集，不补写推测值。

## 样本规模

用同一份本地数据的 `$close` 非空行数记录本实验规模：

| 口径 | 2016 起点 |
|---|---:|
| train 窗口至 2020-01-10 | 2,933,129 |
| handler 窗口至 2026-07-16 | 10,261,457 |

该规模下五个种子均在 16GB 物理内存机器上完成。

## 可行方案

1. 当前配置已验证可在本机从 2016 开始、五种子严格串行运行；这只证明 OOM
   层面的可行性，是否采纳该训练池由用户决定。
2. 后续若需进一步降低内存，可把训练与 test 推理解耦：训练进程的 handler
   `end_time` 只覆盖 valid 末日，模型保存后再由 `eval_ic_multi_pool.py`
   按测试池构造短推理 handler。
3. 分层抽样、样本权重或特征降维会改变训练样本或模型，
   不能与本次“仅改起点”的结论混在一起。

补充：本地 `all` universe 是当前/幸存者式股票池，不是 point-in-time 历史全 A。
复核发现 features 中有 183 个曾在 2016~2020 年有数据的 SH/SZ 代码不在
`all.txt`，其中包含后来退市股票；`all.txt` 还包含 4 个指数代码。因此本实验的
性能结果存在幸存者选择，只能解释为“本地当前 `all` universe”的诊断结果，不能
外推为真实历史全 A 的模型结论。该问题不影响本次 OOM 可运行性结论；若要评估真实
全 A，应另建无指数、point-in-time 的纯股票 universe 后作为新实验重跑。
