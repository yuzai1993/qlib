# Qlib 实验迭代入口

先完整读取 [实验标准](../../../backtest/EXPERIMENT_STANDARD.md)，再读 [Harness 操作协议](../../../docs/research/experiment_harness.md)。标准是实验口径的唯一事实来源；本技能只负责加载流程。

1. 根据用户方向核对研究轨道、相关历史和最新明确的基线选择，冻结唯一改动轴、假设、判读规则、输入身份、预算与停止条件。当前基线从正式登记读取，不能按最高版本号推断；退役或缺失输入必须拒绝启动。
2. 使用 `backtest/scripts/maintenance/experiment_harness.py` 管理合同和状态，先查看 `--help`，按协议在首个真实候选档案保存计划并 `init`。每次启动前运行 `check --state <状态路径>`，检查通过后追加 `start` 事件，再调用既有正式训练/评估入口。工具只检查与记账，不执行研究命令或证明科学结论。
3. 续跑先重读合同、`status`/`check`、正式 registry、本任务进程及已有输出，确认中断位置后行动。沿用原 campaign 和状态，保留累计轮次、科学候选、技术尝试、耗时及 test 暴露事实；新聊天、重试或部分种子完成都不重置预算。配置变化算新科学候选；技术重试保持原冻结配置并使用新 attempt。
4. 每个候选结束后先保存正式指标或失败/中止证据，通过现有登记入口追加正式事件，重建并核验详情及对应总报告，再反思或继续。部分种子、目录存在、零退出码都不足以证明完成；失败无指标时记录原因，不填造数字。
5. 预算到限、连续无新证据、漂移、执行受阻或用户要求停止时，按协议记录停止原因并收尾。先完成全部终态登记和报告，再确认相关进程结束、dry-run、核对审计和执行适用清理；清理受阻要持久化待办，不能标成全部完成。

在用户已授权的方向及预算内自主迭代，不逐轮重复申请开跑。晋升或切换基线、修改标准、生产/实盘操作及新增正式模块或平台结构不在本技能授权内；需要扩大这些范围时先说明具体变更并取得用户同意。一次性适配工具放仓库外任务目录，收尾按现有规则清理。
