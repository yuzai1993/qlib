# CSI1000 B6-M 盘后模拟实盘系统设计

日期：2026-08-02  
状态：用户已批准，允许连续实施  
部署性质：受控演进；仅模拟盘，不自动启用真实资金

## 1. 目标与边界

新建一套独立的 CSI1000 模拟实盘系统，使用研究基线的冻结 B6-M seed 4000 模型和 B2-S 稳态策略，在沪深交易所盘后固定价格交易时段按官方收盘价委托。系统替换旧 CSI300 模拟盘的调度入口，但保留旧配置作为历史审计材料。

生产组合固定为：

- 股票池：CSI1000；benchmark：`SH000852`；
- 初始资金：500,000 元，空仓启动；
- 模型：B6-M v1.0 的 seed 4000 冻结 DoubleEnsemble artifact；
- 稳态策略：Top30 / Drop2 / Hold20 / risk degree 0.95；
- 初始化覆盖层：持仓未满 30 只时每天最多买入预测排名最高的 2 只未持仓股票，不卖出；
- 成交方式：交易日 15:05～15:30 的盘后固定价格交易，价格类型 49，只接受官方收盘价；
- 账户类型：新 QMT 模拟账户；真实资金切换不在本次授权范围内。

本次是生产工程部署，不进行训练、策略扫参、回测选型或基线提升，不新增实验 registry 记录。研究 B6-M / B2-S 的冻结定义仍以 `backtest/EXPERIMENT_STANDARD.md` 为准。

## 3. 策略语义

### 3.1 显式初始化参数

`TopkDropoutStrategy` 新增可选参数：

`initial_buy_count: int | None = None`

默认值 `None` 完全保留历史行为。该参数与 `n_drop` 独立：前者是空仓/欠仓阶段的每日新增速度，后者是满仓后的每日替换上限。新实盘配置显式设置 `initial_buy_count: 2`。

### 3.2 欠仓阶段

若交易决策开始时实际持仓数小于 `topk`：

1. 不产生任何卖出候选，不执行 Drop；
2. 按当日预测分数降序、股票代码升序稳定排序；
3. 跳过已有持仓，选取至多 `min(initial_buy_count, topk - 当前持仓数)` 只；
4. 停牌、无有效收盘价、涨跌停或未成交不会被视作已持有；后续交易日继续按实际券商持仓补齐；
5. 即使已有持仓跌出 Top30，在组合实际达到 30 只前也不卖出。

当组合在某交易日成交后首次达到 30 只，从下一个交易日开始进入稳态。不得在“补齐第 30 只”的同一批次同时 Drop。

### 3.3 资金分配

每只新增股票的目标毛市值固定为：

`决策时总资产 × risk_degree / topk`

本配置即 `总资产 × 0.95 / 30`。目标股数按当日官方收盘价计算并向下取整到 100 股。不会把可用现金平均分给当天的 2 只；若现金不足则按稳定排名顺序逐只缩减或跳过，绝不透支。

稳态换仓继续使用卖出后实际可用资金，但单只买入目标仍以槽位权重为上限，避免少量买入候选吸收全部现金。

### 3.4 稳态与最低持有期

实际持仓达到 30 只后的下一交易日开始使用：

`TopkDropoutStrategy(topk=30, n_drop=2, hold_thresh=20, risk_degree=0.95, only_tradable=false, forbid_all_trade_at_limit=false)`

实盘账本为每个持仓保存首次实际买入交易日。最低持有期按交易日计算：买入日记为第 1 天，只有在决策日前一日已累计持有至少 20 个交易日时才允许卖出。加仓不重置首次开仓日；全部卖清后再次买入则建立新的开仓日。

选股函数由 Qlib 回测策略和实盘订单管理器共享。配置一致性守卫必须比较 `topk`、`n_drop`、`initial_buy_count`、`hold_thresh`、`risk_degree`、可交易限制、费用和成交价口径，防止两侧漂移。

## 4. 信号生成

生产 handler 使用 B6-M 的 `Alpha158Technical`、Alpha158 + range 特征、训练期和 infer processors 原样配置。`SignalGenerator` 不再假设模型具有单一 `.model` LightGBM booster，而是调用冻结 Qlib 模型公开的 `predict(dataset)` 契约；为单日/批量生产构造与训练一致的 DatasetH/handler 数据视图。

每个信号批次必须记录：

- signal date 与目标 trade date；
- 模型 baseline ID、相对路径和 SHA-256；
- handler/config SHA-256；
- 数据日历最后日期；
- 预测股票数、缺失数和稳定排序摘要；
- 原始预测文件 SHA-256。

若目标日特征缺失，正式发布默认失败关闭；`allow_stale` 只允许显式诊断命令使用，不得用于正式调度。

## 5. 账本与发布协议

新系统使用独立 SQLite：

`live_trading/data/csi1000_b6m_b2s_postclose.db`

旧 CSI300 数据库不复用。核心状态包括信号批次、计划订单、发布事件、QMT 回报、成交、持仓、首次开仓日、现金流、每日快照、任务运行和告警。

每个交易日必须持久化一个明确终态，即使无订单也写入 `NO_ORDERS` 批次并发布带校验和的空订单文件。监控、catch-up 和导入器据此区分“正确无交易”与“任务未运行”。

桥接协议升级到 v2：SELL 意图携带账本计划卖出股数；BUY 意图携带 `target_value`，发布侧不再用前一日收盘价提前锁死买入股数。QMT 在交易日 15:05 读取当日官方收盘价，将 `target_value` 向下换算为整手数量并结合实际可用资金裁剪。这样既严格使用前一日预测信号，又按实际盘后成交价落实单股槽位资金。

批次 ID、client order ID 和文件名均由 strategy ID + trade date + sequence 确定性生成。同一交易日重复运行必须命中原批次并核对内容 SHA；内容相同则幂等成功，内容不同则失败关闭且告警，禁止静默覆盖。

发布采用临时文件、`fsync`、原子重命名和 ready marker。QMT 回报导入也以文件 SHA 和业务主键双重去重。

## 6. QMT 盘后执行状态机

QMT 桥接改为定时器驱动，`handlebar` 只保留为兼容唤醒入口；二者调用同一个幂等 `advance()` 状态机，不得各自实现交易逻辑。

状态序列：

1. `WAIT_SIGNAL`：校验 ready marker、schema、trade date、strategy/account、模拟账户环境、文件 SHA 和订单上限；
2. `SUBMIT_SELLS`（15:05）：只提交 SELL，读取并校验官方收盘价，价格类型 49；
3. `WAIT_SELLS`（至少 4 分钟）：持续落盘委托和成交回报；
4. `SUBMIT_BUYS`：重新查询实际可用资金，用官方收盘价和费用预留逐单裁剪数量后提交 BUY；
5. `WAIT_BUYS`：持续查询状态，禁止重复提交；
6. `CANCEL_OPEN`（15:28）：撤销仍未完成委托；
7. `FINALIZE`（15:30）：写最终订单/成交/账户/持仓结果和完成 marker；
8. `SNAPSHOT_READY`（15:31）：允许 Mac 侧导入与生成收盘后快照。

任何价格类型不是 49、成交价与官方收盘价不一致、交易日期不匹配、订单超过上限、文件被修改、未知账户或未知状态都触发失败关闭。桥接不再使用 14:45 盘中委托、价格类型 11、买卖滑点或行情回退价。

## 7. 调度、监控与恢复

所有 shell 入口接收显式配置路径或 config ID，不再硬编码 CSI300。脚本使用严格错误传播和单实例锁，退出码不得被日志/通知步骤吞掉。

建议日程：

- 前一交易日 21:00，在 Qlib 日线数据更新完成后生成当日预测，并发布下一交易日批次；
- 交易日 15:05～15:31 由 QMT 本地状态机执行前一日晚已准备的批次；
- 15:32 起导入成交、账户和持仓；
- 15:35 生成快照、对账和日报；
- 21:00 catch-up 只补偿缺失终态，不重新生成已有不同内容的批次。

调度前通过 Qlib 交易日历确认日期；周末和休市日写 `SKIPPED_NON_TRADING_DAY` 运行记录。每个阶段记录 start/end、attempt、输入/输出 SHA、退出码和错误摘要。

监控重点：

- 信号新鲜度、数据日历覆盖、模型/config SHA；
- `NO_ORDERS` 与漏跑区分；
- 发布与 QMT 消费 marker 一致性；
- 拒单、未成交、撤单和成交价偏离；
- 持仓数、欠仓天数、Hold20 资格和实际/账本持仓差异；
- 现金、总资产、当日收益与 benchmark；
- 调度进程存活不作为任务成功依据，持久化终态才是依据。

## 8. 部署与回滚

受控演进分三阶段：

1. Shadow：完整生成信号与订单，但 QMT 不提交；验证模型、排序、金额、日期、SHA 和对账；
2. 模拟盘小额：新账户以最小一手验证盘后类型 49、成交回报和状态机；
3. 模拟盘全额：切换到 500,000 元和正式槽位金额。

任何阶段失败都保持当前阶段，不自动晋级。真实账户永远需要新的明确用户授权和独立配置；不得通过修改环境变量让模拟配置隐式指向真实账户。

活动调度只引用新配置。旧 `csi300_topk10_live.yaml`、旧模型和历史说明保留但标记为 inactive/unscheduled。此前已清理的旧模拟盘运行数据不恢复。

回滚通过停用新调度、停止 QMT strategy ID 和保留 SQLite/桥接文件实现；不自动重新启用旧 CSI300 任务。

## 9. 验证标准

实现采用测试驱动，至少覆盖：

- 初始化每日仅选 2 只、跳过已持仓、临近满仓只补缺口、满仓次日才 Drop；

- 单股槽位预算、整手取整、现金不足和费用预留；

- QMT 15:05/4 分钟/15:28/15:30 状态迁移、价格类型 49、重启恢复和重复唤醒；
- 配置一致性、独立数据库、活动 strategy ID 和模拟账户守卫；
- shell 错误码传播、监控漏跑/无单区分；
- live_trading 全套回归、相关 Qlib 策略回归、格式和 `git diff --check`。
