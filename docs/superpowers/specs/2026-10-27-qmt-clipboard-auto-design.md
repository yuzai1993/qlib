# QMT 剪贴板自动日流程

用户要求正常日流程不再手填订单、session 或启动每笔交易。沿用现有 Mac 收盘调度、protocol-v2 inbox 和账本导入；Windows 计划任务启动中转，中转定时读文件、经剪贴板查询 QMT 行情/账户、定量下单、写成交与账户快照。QMT 无文件/网络 I/O。

## 实现选择

采用 Windows 中转负责定时与定量，QMT 保持查询/限价执行器。把全部业务移进 QMT 会增加受限环境维护量；重新设计 Mac 发布和账本协议会扩大迁移范围。此实现选择由开发方根据用户的自动化与最小维护要求确定，继续此前已授权开发。

## 正常路径

- Mac 现有 20:00 调度导入当日结果、更新数据并发布下一交易日 `inbox/signal_*.jsonl` 与 checksum `.done`。
- Windows 同一交互用户的计划任务工作日 14:54 启动 `auto`，每秒轮询，只处理指定 strategy、北京时间当天的唯一批次。无信号不下单，旧批次绝不补发。
- 首次通过 poll 获取 session；snapshot 请求返回账户、全持仓、所需股票 tick 与涨跌停。QMT 返回能力字段，旧版执行器不能进入自动下单。
- 14:55 起卖出，14:57:05 起买入，均在 14:59 停止发出新请求。卖单在 14:57:05 后不补发。买入按即时可用资金和预算、现价、手续费定量；卖单不确定或查询失败则不买。卖单已接受但未成交时，仅可用当时实际现金，不预支卖出款。
- 定价沿用现有配置：买现价上浮 0.2% 向上到分，卖下浮 0.2% 向下到分，夹到可用的当日涨跌停。行情必须为当日且不旧于 180 秒。买入保留原目标金额按现价整百股定量，再按限价下的目标金额上限及可用资金/手续费缩量，保证旧账本可导入；科创板至少 200 股，其他支持股票至少 100 股。卖出检查可卖和整手/全部零股。无同名抵销、自动撤单或改价重报。
- 外部本地 journal 先原子落盘 session、完整不可变请求，再写剪贴板。中转重启同 session 继续查询/重发原请求；QMT session 变更且存在未完成请求则停止该日交易，不能重绑定。记录已导出的结果，避免循环重写被 Mac 归档的文件。
- 每秒更新结果/日志；终态批次发布旧格式 `outbound/fills_*.jsonl/.done`。活跃 PARTIAL/UNKNOWN 不伪造成终态。17:00 自动写旧格式账户快照；17:01 正常退出，未确认状态返回非零并留下错误文件。
- 每个日期最多一个 strategy 批次；多个未明确替代的批次拒绝，避免重复计划。手动 MVP 命令仍保留，正常部署使用 auto。

## 边界与交付

只承诺正常日流程自动化。QMT 崩溃后的不确定委托保留人工异常处理，不以自动补单换取表面成功。默认本地 journal 位于 Windows 脚本旁的 output，回执和日志写现有共享目录。Windows 登录会话和 QMT 需运行，注册为 Interactive 计划任务，不能 Session 0。

交付 QMT 增强查询、Windows 自动中转模块/CLI、一次性任务注册 PowerShell、更新部署文档，以及 fake broker/clipboard 的整条发布→成交→现有 Mac 导入测试。不连接实际券商发单，不开启远程生产任务。
