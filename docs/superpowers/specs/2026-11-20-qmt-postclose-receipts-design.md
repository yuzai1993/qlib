# QMT 收盘回执与当日未成交结案

用户已选择：17:00 核对委托、成交和持仓一致后，自动记为“当日未成交”；存在矛盾则保留待核对。已确认成交不得被另一笔非终态委托扣住。

## 行为

- QMT 快照保留原始活动委托，增加全账户 DEAL 查询及独立错误字段。逐笔成交按交易日、市场和成交编号去重，冲突不能静默覆盖。
- 外部执行器在首笔请求发出前保存成交及持仓基线。17:00 后取得当前会话的完整快照，将新增成交逐项匹配本批次委托，并从基线持仓推导盘后持仓；全账户必须一致。
- 只把证据完备的普通当日、正常交易时段提交、已报且零成交委托结案为 EXPIRED（展示含义为“当日未成交”）。UNKNOWN、数据缺失、异账号、额外交易、日期不明、部分成交未终态及持仓冲突均待核对。原始 QMT 状态不改写。
- 已确认终态逐笔导出，不等待整个批次。回执文件不可变，具备落盘后崩溃重启、Mac 归档后重启及累计量导入幂等保护。全批终态后输出完整最终回执。
- 自动结案保存可复算的基线、盘后委托/成交/持仓证据和最终回执摘要。后续交易日只识别证据及归档回执都完整匹配的旧缓存；QMT重连清空备注时只兼容空串，其他委托字段仍严格核对，不同非空备注不得放行。
- 11月20日按用户明确确认结案零成交委托，补入另外三笔准确成交，撤下旧的11月23日批次，重建日报及计划。不得以券商现金快照替换账本现金。

## 边界

QMT 内置 Python 3.6，外部 relay Python 3.8+，仅标准库。保留既有下单窗口、额度、订单编号及会话重放保护。此次不改变发布端既有“由QMT决定执行”的控制策略；修复账本后重新生成计划。17点核对失败必须保留明确原因，不能伪造撤单回报。

## 验证

覆盖正常结案、17点前拒绝、逐笔成交迟到/冲突/缺失、非本批交易、部分成交、持仓差异、账号/日期/会话错误、缺失基线、回执重放与故障恢复。运行现有剪贴板及账本回归测试，部署后只读核验；不通过实盘下单测试。
