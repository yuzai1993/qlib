## 1. 设计总览

**核心假设**：模型多头尾部失效源于 (a) 训练窗缺"防御尾部会输"的 F/T 态样本，(b) 特征缺先验的风格状态信号。二者必须同时修，故主实验为组合臂。

| 臂 | 训练池/窗 | 特征 | 训练加权 | 角色 |
|---|---|---|---|---|
| **B6-M** | csi1000，2016-2020（现役冻结模型） | Alpha158+range | 自然 | **现役基线参考行**：直接用现有五种子产物在新评估协议上推理，回答"新方案是否胜过现役模型"；因池/窗不同，不作归因对照 |
| M0 | 全A，2004-01~2020-07-31 | Alpha158+range（B6-M 原版） | 自然 | **协议内归因对照锚点** |
| **M3** | 同上 | + regime 特征（A0b 产出） | 风格平衡权重 | **主实验臂** |
| M1 | 同上 | + regime 特征 | 自然 | 可选归因臂 |
| M2 | 同上 | 原版 | 风格平衡权重 | 可选归因臂 |

模型结构/超参全部冻结 B6-M 版本（DoubleEnsemble、lr=0.1、H40+CSRankNorm、RankIC 早停）；只动数据与特征。五种子 [42,1000,2000,3000,4000]。

## 2. 数据与时间划分

### 2.1 训练池：全A

- 剔除：ST（名称缓存可用时）、上市 < 60 交易日次新股、B 股、北交所（默认，待确认）。
- 本地数据 2003-01 起；2003 年留作滚动窗 warmup，**训练样本自 2004-01-02 起**。

### 2.2 训练窗与 purge

- train：2004-01-02 ~ 2020-07-31（**不含任何 post-924 样本**）。
- H40 训练标签向前看 41 个交易日：剔除 2020-06 初之后标签窗跨过 2020-07-31 的样本（`PurgedHorizonDataset(label_horizon=40)`），杜绝 train→test 泄漏。
- 训练时代风格存量（月）：**D 136 / F 47 / T 16**（对比 B6-M 旧窗 2016-2020：F/T 各仅 4 个月）。

### 2.3 valid = test：采样测试集兼做早停（v3 指示 3）

- **不再从训练时代留出 valid**。早停 valid 锚点 = 2.4 节冻结的 70% 采样日集，test 评估也在同一日集上。训练时代全部月份进 train（样本量最大化）。
- **风险声明（预登记进解读规则）**：早停轮数在 test 上选取，最终指标含轻微乐观偏差。缓解：
  1. 超参全部冻结 B6-M 版本，早停轮数是唯一自由度；
  2. 各臂（M0/M1/M2/M3）同等对待，**臂间对照（Gate 1）公平不受影响**；
  3. B6-M 参考行为纯推理，完全不受影响；
  4. 与现役基线的绝对差距解读时注明该偏差方向（对新臂略有利）。
- 该做法与规范"禁止用 test 调参"冲突，**用户 2026-08-09 明示豁免（仅限早停轮数这一自由度）**。
- 工程：`RankICEarlyStoppingDEnsembleModel` 的 valid 锚点需支持非连续日期列表（A0d 验证）。

### 2.4 test：风格分层采样，70% 使用 / 30% 封存（v3 指示 4）

- 候选期：2020-08-03 ~ 2026-07-31（自然构成：D 50 / T 15 / F 7 个月）。
- 第一步：按**全历史占比 D/F/T = 69.6/19.1/11.3** 生成完整分层清单（F 稀缺约束，136 个交易日全取，反推总量 713 天）。
- 第二步：**分层内随机 70/30 拆分**（seed=42），**已于 2026-08-09 生成并冻结**（脚本 `backtest/scripts/sample_regime_test_dates.py`）：
  - `test_dates_stratified_70.csv`（**499 天：D 347 / F 95 / T 57**）——本实验的 valid+test；
  - `test_dates_reserved_30.csv`（**214 天**）——**封存**，本实验不评估、不查看，留给后续"增加最新样本"实验作未污染评估集。
- 注意：靠近数据终点（2026-08-07）的采样日在 h40 口径下无完整前视窗，仅在 h40 一列中剔除，其余期限不受影响。
- 两清单随 configs 入 Git，开跑前预登记，此后不得改动；风格标签用 `monthly_regime_3style.csv`（事后标签，仅用于评估设计，不进入模型输入）。
- 附加报告：完整连续窗（2020-08~2026-07）的自然整体 IC 作参考行（与分层口径对照）。
- 统计注意：
  1. 非连续采样下 RankICIR 的时序 std 解释需注明；
  2. h>1 期限存在重叠窗口，显著性按保守读；
  3. F 态 70% 后仅 ~102 天，分层 IC 置信区间宽，结论看方向与幅度一致性，不追小数点。

## 3. 训练加权（M2/M3）

- 日级样本权重：目标风格占比 **D/F/T = 55/30/15**（自然 68/24/8 → F ×1.3、T ×2，温和上调；不做 1:1:1）。

- 实现：LightGBM `sample_weight` 透传；DoubleEnsemble 子模型加权兼容性在 A0d 验证。若内存吃紧，D 态部分改**下采样**实现（见第 7 节），等效于权重且直接减样本量。
- 训练期风格标签为事后标签：仅作训练加权手段，推理期不使用，无前视泄漏。

## 4. 评估口径（v3 指示 5 重写）

### 4.1 测试池

csi300 / csi500 / csi1000 / **全A**（按规范过滤次新与 ST）。Phase M 只算 IC 类指标。

### 4.2 指标定义

- 期限集 h ∈ {1, 5, 10, 20, 40}，标签 `Ref($close,-(h+1))/Ref($close,-1)-1`；h40 即训练 H40 口径。
- 两个汇总指标：
  1. **h1 RankIC**（与历史实验、B6-M 数字可比的传统尺）；
  2. **五期限均值 RankIC** = mean(h1, h5, h10, h20, h40 的 RankIC)，等权。
- **北极星指标 = 全A池、不分风格、五期限均值 RankIC**（五种子均值）。
- 依据：诊断发现 B6-M 的 h40 RankIC 衰减 46% 而 h1 仅 7%，五期限均值能暴露 h1 看不见的映射退化。

### 4.3 报告矩阵

每臂（含 B6-M 参考行）给五种子均值：

| 维度 | 池 | 指标 |
|---|---|---|
| ① 整体（不分风格） | csi300 / csi500 / csi1000 / 全A | h1 RankIC(+IR)、五期限均值 RankIC(+IR) |
| ② 分风格 D/F/T | **仅全A** | 同上两项 |
| ③ 北极星 | 全A整体 | 五期限均值 RankIC + 逐种子 pairwise_win_count |
| ④ 尾部诊断（副） | csi1000、全A | top22/top50 − 全池等权年化超额，整体+分风格 |

Pearson IC/ICIR 落盘作附录，不进主表。

### 4.4 工程

扩展 `backtest/scripts/eval_ic_multi_pool.py`：`--horizons 1,5,10,20,40`、`--date-list <csv>`、`--regime-labels <csv>`（仅全A切分）、`--tail-topk 22,50`、汇总输出五期限均值列。内部仍走 `eval_protocol.daily_ic`；改动配对拍测试（h1 全窗口径与现版本逐位一致）。

## 7. 工程、内存与算力（v3 指示 2）

### 7.1 内存风险评估

- 样本规模：全A ~2400 只/日均 × ~4000 交易日 ≈ **10M 行 × ~165 特征**。纯特征矩阵 float32 ≈ 6.6GB，**但实际峰值远高于此**：
  - qlib handler 管线（Alpha158 表达式计算 + CSRankNorm 等 processor）中间体常为 float64，峰值可达特征矩阵的 3~5 倍；
  - DoubleEnsemble 的 feature selection / sample reweight 循环会持有数据子集副本；
  - LightGBM 构造 `Dataset` 时若不释放原 DataFrame，会双份常驻。
- **A0d 实测结果（2026-08-09，两轮）**：
  - 2 年切片（2018-2019，165 万行）：峰值 RSS 4.53GB，加载 108s；

### 7.2 分块准备架构（A0d 实测后定案，2026-08-09）

单 handler 全跨度被否决，改为**训练数据分块预处理 + 独立 valid 推理**：

1. **逐年分块预处理落盘**：对 2004~2020 每年建一个短跨度 handler（前置 6 个月 warmup 供 Alpha158 滚动窗，只保留本年行），processor 后 learn 数据降为 float32 parquet 落盘。逐年峰值 ~2-3GB；缓存各臂/各种子复用（M0/M3 特征集不同，各一份）。CSRankNorm（label 逐日截面）与 DropnaLabel 均为日级操作，分年处理无跨界影响。
2. **D 态下采样**：组装训练矩阵时对 D 态日按目标占比（55/30/15）下采样（等效权重、直接减行数），残差用 day 级权重微调（`RegimeWeightedDEnsembleModel`）。
3. **组装 + 训练**：拼接年度 parquet 成单一 float32 train 矩阵（下采样后 ~5-6GB），经 `_PreparedTrainValidDataset` 适配器直接喂 DoubleEnsemble（绕过全跨度 handler）；lgb.Dataset 构造后释放中间副本。
4. **valid 锚点独立准备**：单独的推理 handler（2019-08~2026-07 跨度，DK_I）prepare 后过滤到冻结 70% 日集（~240 万行，~1.5GB），随后释放 handler。
5. **test 推理**：训练后由 `eval_ic_multi_pool.py` 现有机制按池独立构建推理数据集，与训练进程分离，无叠加峰值。

预计训练进程峰值 ~10-11GB（train 矩阵 + valid 帧 + LightGBM bin），16GB 可行；正式跑时关闭其他大内存程序。兜底：`kernels` 调低；训练窗起点后移至 2007-01（保留 2007-11/2008-09 关键 F 段）需登记为设计变更。

### 12.5 口径 v2 修正（2026-08-15，用户四点指示）

12.4 节的审计给出了正确的问题，但其中两条**修正手段本身有偏**，本节推翻并重做。
所有 v2 结果落 `backtest/result/eval_regime_head_v2/`，v1 结果保留在
`eval_regime_head/` 供口径变更影响对比。执行脚本 `backtest/scripts/run_head_eval_v2.sh`。

**1）撤销"排除 h1"的稳健排序键（推翻 12.4-缺陷1 的修法）**

12.4 以"h1 是 H1 臂主场标签"为由删 h1，但 h5/h10 同样分别是 H5/H10 臂的主场格——
删 h1 只是把主场优势让给短标签的另两臂，不构成中立修正。正确的框架是：

- 评估期限集 h∈{1,5,10} 由**策略持有期**决定（B4-S `hold_thresh=2 / n_drop=2 / topk=22`
  的有效持有期约 11 日），与参赛臂无关。一旦这样固定，任何臂在任何格上赢都是合法的。
- 因此 **9 格等权均值是唯一北极星**，不再设第二排序键。
- 主场优势改用**对称诊断**呈现：每臂拆出主场格（h = 其训练标签期限）与客场格（LOHO），
  看优势是否只集中在自家期限。H40 三臂的主场期限落在网格外，主场列为空、客场即完整
  9 格；这一不对称如实标注，不靠删格掩盖。
- 对 H1 的降级判据因此**不再来自期限排除，而来自可成交性**（下条）。

**2）次日涨停/停牌在评估内剔除（把 12.4-缺陷2 从"注脚"变成"口径"）**

评测标签在 t+1 收盘建仓，故只看 t+1 是否可买：

- 涨停封板：t+1 相对 t 涨幅 ≥ 板块阈值（主板 9.5%；创业板/科创板 19.5%，
  创业板 20% 自 2020-08-24 起，之前按 9.5%）；
- 停牌/无撮合：t+1 成交量为 0。

这些样本同时从 **top-k 候选池和等权基准**中剔除（同口径，否则超额不可比）。
实测全A 全窗 t+1 可成交率 98.54%。实现见 `eval_ic_multi_pool.entry_tradable_mask`，
开关 `--exclude-limit-up`。全截面 RankIC 保持不过滤，以维持与历史 registry 的可比性。
卖出侧跌停未剔除，仍是已知缺口。

**3）删除 Hit@k**：全A ~4000 只时 k=22 随机重叠期望仅 0.55%，无判别力，已从
计算、报告与单测中移除。

**4）评估日改为测试窗全部交易日**（原为 70% 分层抽样 499 天）

评估日连续后换手率可直接估算，补上 12.4-缺陷5：

- 换手 = 相隔 h 个交易日的 top-k 单边换手率（h 日持有 → 每 h 日换一次仓）；
- 年化成本 = (238/h) × 换手 × 0.092%（买 0.021% + 卖 0.071%）；
- 净年化超额 = gross − 年化成本，作为 TopkDropout 净收益的**上界**
  （不含冲击成本、不含 n_drop 缓冲）。

**代价**：30% 封存集已并入本次评估，"加最新样本"实验须另划样本外窗。

**工程**：`daily_head_metrics` 改为 `daily_head_panel`（向量化 rank + 逐日选中集合，
供换手计算），标签统一升 float64 消除逐日累加漂移；与旧循环实现在真实数据上对拍一致
（k=10/22，含/不含可成交掩码）。新增 `topk_turnover` / `grid_mean_ir`，单测 39 项通过。

**推翻 12.5 的两条结论**

1. **"H5 不是晋升候选（净超额 0/5 输给 H40，因为换手更高）"——不成立。**
   头部口径按"每 h 日全额换仓"折算成本，而 B4-S 的 `n_drop=2 / hold_thresh=2` 机械地
   把实际换手锁死在 **21~22x 年化单边，五臂相差 <4%**（M0 H5 22.0x、M0 H40 21.4x、
   B6-M 21.2x）。短标签的换手成本劣势是头部口径的产物，在真实策略里不存在。
   → 头部口径的"扣费净超额"只应作 gross 的上界参考，**不应用于跨标签期限排序**。
2. **"方案 1（加 regime 特征端到端学）无效，应走方案 2（按风格切期限）"——只在 H40 下成立。**
   regime 特征与标签期限有强交互且方向相反：H40 下加特征**有害**
   （M3 H40 0.827 vs M0 H40 1.249，−0.42）；H5 下加特征**有益**（+0.17）。
   自洽解释：40 日标签已把风格切换平滑掉，11 个日频风格特征给不出可用信号、只增加过拟合
   维度；5 日标签的收益才随当期风格摆动，特征才有发力点。
   → 12.2/12.4/12.5 三次否掉方案 1，都是在 H40 上做的，不能外推到短标签。

**旁证：Phase M 头部口径本身是可信的**

头部 NS 排序（M3 H5 1.474 > M0 H10 1.330 > M0 H5 1.306 > M0 H40 1.249 > B6-M 0.652）
与后段回测夏普排序（M3 H5 1.28 > M0 H5 1.18 > M0 H10 1.11 > B6-M 0.77 > M0 H40 0.75）
仅相邻位互换。v2 口径对当前段真实表现有判别力；它与全周期夏普不一致，是全周期夏普被
前段污染，不是口径失效。

**Beta 说明**：头部 IR 是相对当日全A 等权均值的横截面超额，与指数 Beta 无关；回测夏普含
Beta 暴露。全A 长窗训练的 M0/M3 系列组合 Beta 0.85~0.95，csi1000 池内训练的 B6-M 仅 0.59。
B6-M 的低波防御风格，正是它前段夏普高、后段（小盘高波）跟不上的同一个原因。
表中 Alpha 已按 CAPM 扣掉 Beta 贡献，M3 H5 后段的 Alpha 优势不是靠 Beta 换来的。
