## 设计

### 现状与耗时证据

`prepare/prepare_regime_train_chunks.py` 对 2004—2020 年逐年创建 handler，计算 Alpha158 + range（164 个特征），经过标签 DropnaLabel / CSRankNorm、上市龄过滤后保存 165 列年度文件。正常完整年份带前置 6 个月和后延 3 个月数据，2020 年截断到训练末日。

2026-11-03 00:23 的本轮日志显示：2014 年 488,561 行、351 秒，其中 Loading data 为 346.554 秒。当前任务适配器将取数并发设为 2。瓶颈在重新物化数据和特征，单纯加速写盘无法解决。日志：`backtest/experiments/models/training-target/h20-legacy-rebuild-20261102-v1/docs/runner/prepare.log`。

已有 `build_regime_alt_labels.py` 可以不重算特征而替换 H 标签，但依赖 m0 年度块的行索引；当前年度块已被 H40 标签有效性裁剪。`train_regime_arm.py` 另有早停验证缓存。三处目前都有按文件存在跳过或复用的路径，需要统一身份校验，不能只保留文件。

### 方案选择

- 只提高并发：可能缩短冷构建，但每轮仍重复计算，也增加内存压力；不作为第一阶段。
- 只保留原年度 pickle：改动小，可先获得跨轮复用收益，但它带 H40 样本语义，不能冒充通用特征缓存。
- **采用：先给原配方增加身份校验与共享生命周期，再分离纯特征、标签和样本协议。** 可以逐步验证，也能在切换出现差异时退回兼容读取。第一版保留 pickle，不同时更换存储格式。

### 缓存分层

1. **共享特征层。** 在 label 的 DropnaLabel / CSRankNorm 之前取特征，保留完整、有序的日期—股票索引；只应用与标签无关且被清单记录的特征处理。按年存储，保持列顺序、float32 转换时点及非有限值语义。纯特征必须重新物化或来自可证明完整的输入；不得由旧 H40 过滤后的年度文件反推缺失行。
2. **标签与样本协议层。** 缓存原始 H 标签及其有效掩码，按显式协议确定截面、排名、上市龄和训练日期筛选顺序，生成最终训练标签和样本索引。标签 key 同时依赖原始数据身份和精确样本/排名协议；禁止跨协议共用同名 `h20_csrank.pkl`。
3. **验证集层。** 早停特征、标签、可交易掩码单独建清单，绑定评估窗、股票池、ST/上市/流动性/涨停过滤来源及相应代码、参数；不只按 `valid_frame_t5h5es.pkl` 文件名命中。不同早停指标只有在所需数据语义完全一致时才共享。
4. **实验装配层。** 各实验只记录采用的缓存 key / 清单 SHA、样本协议、训练日期与权重来源；五个种子读取同一份只读数据。模型超参或种子改变不触发特征重算，权重改变也不重算特征。

历史兼容是硬性要求：历史 H40 的“先排名后上市过滤”和 H20 overlay 的“先对齐旧 H40 / 上市过滤索引再排名”必须分别保留。不得借本次工程优化统一排名顺序、强制七 H 共同样本或悄悄去掉历史 H40 样本约束。未来研究若要改变样本协议，仍需在自己的实验配置中明确冻结。

### 身份、失效与写入

- 清单记录 schema、类型、配方、实际特征表达式与列序、处理器及 fit 参数、数据依赖、股票池、日历、时间窗/warmup/标签截止、相关源码与数值环境版本、dtype、样本协议、分块路径、文件 SHA、逻辑索引/数值摘要、行列数和大小。不要把整个仓库 Git SHA 当配方身份。
- 数据身份来自真实依赖的内容指纹，不只用 `data_version` 日期或路径。第一版按实际读取的字段文件、股票池和日历等依赖做保守内容校验；每次准备统一建立一次快照，供各年度及五种子使用，不能为每年重复扫描同一批原始文件。没有可信冻结快照时，准备/恢复时重新验证依赖。
- 日期、大小、mtime 只能快速筛查，不能作为最终真实性证明。历史数据修订、特征源码/表达式变化、样本规则变化或验证过滤变化，分别使对应层失效。
- 初版对相关源文件追加也可保守失效，不实现按时间切片的精细增量更新。先保证不会误命中，再优化冷构建。
- 没有清单、校验失败或来源不明的旧文件明确拒绝复用。已退役或缺失的研究输入维持现有拒绝逻辑，不自动替代。
- 共享目录放在现有 `backtest/datasets/regime-adapt-cache/shared-v1/` 下，按类型/key 分隔。旧路径只用于显式兼容模式；不得用符号链接或静默搜索把旧文件当新输入。
- 同 key 写入使用跨进程锁；临时块写入、校验、原子替换，最后原子提交完整清单。读取方只接受完整提交。中断续跑只使用清单确认的完整年度；残留临时块不算命中。
- 活动任务使用期间将数据版本与缓存保持只读。准备时发现输入在构建前后改变，拒绝提交；后续发现漂移则拒绝继续拟合，不修改旧缓存迎合新输入。

### 保留与清理

新增缓存被明确分类为可复用研究数据，不作为实验结束即删的无后续用途临时文件。实验输出、模型、预测、registry 和报告仍遵守原有规则。

工程默认：共享缓存总量软上限 **20 GiB**；优先保留当前使用的有效版本，未引用的旧版本按最近使用时间淘汰。全部活动任务的输入依赖及构建中的 key 受保护；不能用固定“最近两份”覆盖活动依赖。

缓存清理是统一维护入口的显式独立模式，默认 dry-run，实际删除必须再次验证清单、文件身份和活动引用。既有 `--result-retention platform --only-result` 的行为完全保留，不顺带清缓存或 mlruns。缓存所有权不能只写在某次实验的临时脚本里。

活动引用与清理使用同一管理锁：先登记引用再开放读取，清理持锁复核后删除。异常退出的引用不可仅凭租约时间或 PID 消失回收，须核对对应任务终态、进程身份和正式状态。存在未知使用者、清单损坏或待清理任务时保守保留。若受保护文件超过 20 GiB，报告实际占用和超限原因，不自动删除保护项或扩大上限。

实验收尾保留缓存清单及使用回执，释放已结束任务的引用；任务专属装配缓存、临时文件和失败写入继续按精确所有权清理。原冻结合同/历史清单不改写。对未来任务更新 Harness 文档中的分类规则，不修改实验标准的评测或模型保留要求。

### 验收与预期收益

- 正确性：同数据、同配方下，新旧训练矩阵的索引与顺序、特征列、float32 特征值、标签值/NaN/Inf 掩码、样本数和权重完全一致；验证帧与可交易掩码一致。排名并列、上市边界、年界、2020 截断和缺标签均要覆盖。
- 复用性：第二次准备相同数据时，特征构建函数调用数为零；新增 H 仅计算缺少的标签/协议层；五个种子不会重复物化年度特征。
- 安全性：源数据/源码/协议变化明确 miss 或报错；半成品、损坏和未知来源拒绝使用；并发写入不会产生相互覆盖，活动依赖不会被清理。
- 性能：分别记录冷构建、热命中校验与加载、标签构建、训练装配耗时，以及进程树峰值内存、磁盘读写和容量。热准备相对相同口径冷构建减少 **至少 80%** 为待实测目标，不承诺具体分钟数；报告计入指纹校验和标签准备，不能只计读 pickle。
- 首次创建新的纯特征缓存仍需冷构建。预期收益主要发生在后续同数据同特征的迭代；不承诺模型训练本身更快。
