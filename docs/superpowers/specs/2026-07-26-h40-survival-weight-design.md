# H40 生存率加权标签实验设计

## 背景与目标

上一阶段在 Top30/Drop1 的 valid 持有期分布上冻结了 20、40、60 日累计标签和
60 日生存率加权标签。固定一日 test 评测显示，在 CSI1000 上，生存率加权 H60
相对累计 H60 的 RankIC 从 0.04047 提升至 0.04119，RankICIR 从 0.27375 提升至
0.32161。该结果说明生存率权重可能改善目标池上的排序稳定性，但尚不能回答 H40
下的权重形状应当更平、更陡还是直接采用生存率。

本阶段只做 Phase M 标签实验，不运行策略回测。目标是在冻结的 Top30/Drop1
valid 持有期分布上构造一组可解释的 H40 权重族，并以 CSI1000 为主目标池评估。

## 实验规范变更

研究主目标池由 CSI300 改为 CSI1000，但 B1 模型定义、训练池、三个测试池和
时间划分保持不变。

- HTML 的测试池顺序与主指标高亮优先 CSI1000。
- Phase M 逐种子成对比较使用 CSI1000。
- 候选资格仍要求 CSI300、CSI500、CSI1000 三池平均 RankIC 全部严格超过 B1。
- 合格候选排序依次使用：
  1. CSI1000 RankIC 增量；
  2. CSI1000 RankICIR 增量；
  3. 三池 RankIC 平均增量。

该变更写入 `backtest/EXPERIMENT_STANDARD.md`，不改变当前 B1，也不自动提升任何
实验为新基线。

## 冻结候选

令 `S(a)` 为上一阶段仅使用 valid 的 Top30/Drop1 持仓生存概率，`a=1..40`。
三个候选均采用未来逐日简单收益

`r_a = Ref($close, -(a+1)) / Ref($close, -a) - 1`

并按下式构造标签：

`y_p = sum(w_p(a) * r_a), w_p(a) = S(a)^p / sum(S(j)^p)`

候选在打开本阶段 test 指标前冻结：

| exp_id | p | 预注册假设 |
|---|---:|---|
| `label-design/survival-p05-h40` | 0.5 | 更平缓的衰减保留中后段信息，可能提高 CSI1000 RankIC |
| `label-design/survival-p10-h40` | 1.0 | 直接匹配持仓存续概率，预期在 RankIC 与 RankICIR 之间取得平衡 |
| `label-design/survival-p20-h40` | 2.0 | 更前置的权重降低远期噪声，可能提高 CSI1000 RankICIR |

累计 H40 和生存率加权 H60 使用上一阶段已登记结果作为对照，不重训、不改变。
不增加混合比例、额外窗口或其他事后参数。

## 数据隔离与选择

- 训练池：CSI1000。
- 种子：`[42, 1000, 2000, 3000, 4000]`。
- valid：2020-01-13 至 2021-07-15。
- test：2021-07-16 至 2026-07-16。
- H40 标签引用到 `t+41`，训练与 valid 边界使用 41 个交易日 purge。
- 三个候选先在 valid 上按 CSI1000 RankIC、CSI1000 RankICIR 排序。
- 候选与公式冻结并校验哈希后，才允许读取本阶段 test 指标。
- test 仍评估 CSI1000、CSI300、CSI500；报告顺序以 CSI1000 为首。

上一阶段 test 结果启发了本阶段问题，因此本轮属于自适应后续实验。即使 test
表现良好，也不能将其解释为完全独立的首次样本外验证；registry 和报告备注必须
明确这一限制。

## 输出

每个实验在 test 报告中显示两行：

1. `eval_1d`：固定一日标签，作为正式可比指标；
2. `eval_self`：候选自身 H40 标签，仅作为可学习性诊断。

registry 保存三池四项指标、CSI1000 五种子成对比较、候选公式与 manifest 哈希。
HTML 由 registry 自动生成。实验结束后按修改后的 CSI1000 优先规则运行统一清理，
只保留 B1 和最佳完整五种子候选。

## 验证要求

- 标签权重完整覆盖 1..40、非负且和为 1。
- `p=1` 与原生存率构造在相同 horizon 上完全一致。
- 所有配置为 `train_only`，训练池、时间和种子符合规范。
- test 打开前 manifest 哈希保持不变。
- 报告第一行为 B1，候选各有 `eval_1d`/`eval_self` 两行。
- 清理器 dry-run 明确显示 CSI1000 排序依据和唯一保留候选。
