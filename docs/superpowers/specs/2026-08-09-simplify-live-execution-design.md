# 实盘信号与 prType=49 调试链路简化设计

## 背景与目标

当前发布端同时承担信号生成、账户模式判断、LIVE_OK/PR49_LIVE_OK 授权和执行闸门，导致主策略测试与 QMT 账户选择耦合。目标是把职责收敛为：macOS 只生成并发布可审计信号，QMT 端由用户决定是否启动、绑定模拟账户或真实账户；prType=49 另起独立 QMT 调试策略。

## 已确认的边界

1. 主链路正常发布下一交易日信号，不再创建或检查 `LIVE_OK`、`PR49_LIVE_OK`、`LIVE_TRADING_CONFIRM`，也不判断 SIMULATION/REAL。
2. 主链路仍保留批次编号、原子 `jsonl/.done` 发布、发布日志、账本、成交回执导入和只读监控；这些用于审计和对账，不作为发布闸门。
3. 下一次主策略信号按 B4-S 基线正常生成。卖出测试前，显式把上次买入标的覆盖为 SELL；覆盖必须记录原始预测、覆盖原因、操作者和最终订单，不能修改原始预测文件。
4. prType=49 使用独立 QMT 策略/配置/共享目录，不接主链路监控、不依赖主账本、不产生任何 LIVE_OK 类 marker。用户在 QMT 中单独启动并自行选择账户。

## 组件职责

### macOS 主发布端

`run_publish_signals.py` 只负责加载 B4-S 配置、生成预测、读取已导入的持仓快照、规划订单、写账本并原子发布到共享目录。`mode` 和 broker environment 不再决定能否发布；保留字段仅作为批次审计元数据时，不能形成 REAL/SIM 闸门。发布失败只由输入无效、批次冲突、文件系统或账本错误触发。

执行状态表可以继续被监控读取，但 `ACTIVE/PAUSED` 不再阻止信号发布；若需要暂停，由用户停止对应 QMT 策略或不启动消费端。

### 主策略人工卖出覆盖

新增一个显式命令行工具（名称在实现计划中确定），输入已有批次/上次买入标的、数量和交易日，读取最近一次已发布的原始订单，生成新的覆盖批次。覆盖文件包含：`source_batch_id`、`override_id`、原订单、最终订单、原因、时间和操作者。工具拒绝不存在标的、数量为零、超过持仓或覆盖到不属于主策略的批次；重复运行必须幂等。

### prType=49 独立调试策略

新建最小化 QMT 策略入口和独立配置，支持明确的 BUY/SELL、证券代码、数量、价格策略及 `prType=49` 参数，输出完整请求/回报/异常日志到共享目录。它不读取主链路 marker，不调用主监控，不写主账本。测试顺序为：一手买入，确认委托/成交/回报，再于下一交易日一手卖出，最后人工核对 QMT 结果。

## 数据与安全约束

- 主发布仍使用临时文件 + `fsync` + 原子改名，并以 `.done` 校验和作为消费可见性标记。
- 主链路继续导入 QMT 成交和账户快照，保留对账能力；对账异常报警不阻止下一次信号发布，除非文件或账本损坏。
- 删除旧 marker 生成、检查和 cron 依赖，避免出现“文件已发布但 marker 未生成”的假阻塞。
- 明确记录一个有意的操作风险：macOS 发布后，任何正在运行且指向该 inbox 的 QMT 策略都可能消费信号；账户和实盘/模拟选择完全由 QMT 操作员负责。

## 验证计划

1. 发布回归：无 marker、无模式环境变量时，主链路仍能生成并原子发布批次；重复批次幂等，账本和监控读取正常。
2. 卖出测试：对上次买入标的生成人工 SELL 覆盖，验证 QMT 消费、成交回执导入和持仓变化。
3. prType=49：独立策略完成一手 BUY → 次日一手 SELL 闭环，检查 QMT 原始日志、委托状态和成交结果；主监控不应产生该策略告警。
4. 全量 `live_trading` 测试及跨平台共享目录原子性测试。

## 迁移与回滚

先保留旧脚本文件作为兼容入口，但移除其主流程调用；部署时停止旧 cron/marker 任务，启用新的发布命令和独立 prType=49 QMT 策略。若回归失败，可恢复旧入口和旧 cron，不删除已有账本、批次或回执。
