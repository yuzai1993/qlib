# 量化研究平台设计草案

> 本文记录第一阶段独立服务设计。后续部署与数据读取架构已由 `2026-10-28-quant-platform-single-service-design.md` 替代，当前平台在原 qlib 工作区以单服务运行。

日期：2026-10-28（Asia/Shanghai）

状态：2026-10-28 用户批准独立平台方案，并授权直接完成实现与验证、无需逐项确认。

依据：用户要求在现有实盘页面上扩展实盘监控、离线实验、分析历史三部分，且改动不能影响实盘交易。

## 1. 目标与边界

将现有监控能力整合到统一的中文研究平台，提供清晰的模型/策略版本历史、指标查询对比及可追溯的分析报告与代码。首期离线实验以用户指定的 `qlib_exp/backtest/experiments/phase_m_v1_report.html` 和 `phase_m_v1_bt_report.html` 为入口；数值从对应 registry 与 JSON 摘要读取，不抄写 HTML 数字。

本次属于展示与档案管理工程，不进行训练、回测、策略调参、baseline 晋升、产物清理或交易切换。实验规范以 `backtest/EXPERIMENT_STANDARD.md` 为准。研究 baseline 与实际交易配置分别标识。

## 2. 方案选择

推荐 **独立平台服务，复用监控 HTTP API**：新增 `quant_platform/` 模块、静态资源、独立启动入口及测试。原监控继续在 `127.0.0.1:8082` 运行，平台拟在 `127.0.0.1:8090` 运行（启动前检测端口，绝不抢占）。新平台仅代理原监控明确白名单中的 GET 接口，不接触生产 SQLite 或交易共享盘。页面延续现有功能，重做统一导航和视觉层。优点是新增服务可独立验证、停用和回退；代价是实盘视图依赖原监控服务在线。

备选 **直接扩展现有 Web 服务**：文件较少，但修改原静态目录会立即影响现网页面，启动旧应用工厂还会初始化数据库，隔离与回退较差。除非用户明确选择，否则不采用。

不另搭托管云网站：本任务依赖本机研究文件和本机实盘监控，沿用本地 Python/FastAPI 与浏览器页面最直接。前端先采用无需构建的 HTML/CSS/JavaScript，避免为首期引入另一套运行环境。用户已授权由实施者决定后续细节。

## 3. 页面与交互

### 3.1 统一布局

左侧固定主导航为「实盘监控」「离线实验」「分析」，右侧是模块内容、标题、数据更新时间和必要操作。建议深蓝导航搭配浅色内容区，青色强调、克制卡片、清楚的数字对齐与高密度指标表；盈亏色语义延续现有页面。适配窄屏，表格可横向滚动，键盘可操作筛选与弹窗。

### 3.2 实盘监控

保留「概览」「批次与成交」「预测信号」全部既有能力，包括账户与基准曲线、持仓与现金、费用、批次展开与失效状态、信号日期、代码/名称联想、Top/Bottom、单股曲线、排序及分页。保留手动浏览器刷新方式、请求世代检查与图表释放行为。新平台独立存放展示资源，不修改 `live_trading/web/static/`。

代理仅允许现有 GET 端点，固定 loopback 上游，不接受请求指定上游、不跟随重定向；设置超时、响应大小限制。上游失败显示实盘模块不可用，并继续允许使用研究与分析。不得回退为直接读取或初始化生产数据库。

### 3.3 离线实验

两个独立页签：「模型评估」「执行策略」。每个保留历史 baseline、分年、分风格、实验记录四个视角。历史版本显示晋升版本、当前标记、实验标识、来源和原始报告入口；不由指标大小自行推断 baseline。

- 模型主表展示 top3×h5 扣费净年化、HAC 波动、扣费夏普、非扣费年化、日换手、全局 h5 RankIC。年度与风格只取 top3×h5，RankIC 不铺入没有该指标的切片。
- 执行策略展示 CAGR、夏普、Alpha、Beta、最大回撤、Calmar、年化波动和换手；算术年化明确为审计指标。
- 支持版本/实验名称与 ID 搜索、状态/方向筛选、年度 2020–2026 或风格 D/F/T 查询、指标切换、排序、同口径多版本对比和 CSV 导出。CSV 避免公式注入。
- 默认对比历史 baseline；实验记录保持独立，用户可从合格实验详情加入同口径对比。失败、运行中、归档记录有明确状态，不把缺失结果显示为 0。
- 比较必须匹配研究轨道、评估池、时间窗、信号聚合及评估口径。单种子结果、延长窗口诊断、指定池诊断单列，不计算与正式 baseline 的混合差值。
- 五种子完整性检查读取真实种子信息，不能仅凭存在 `ensemble` 字段判断；官方指标读取合成信号，历史 fallback 明示来源并排除正式比较。
- 模型正式主格固定读取 `pools.all.ensemble.head['3']['5']`，不盲用历史 JSON 顶层 `primary_cell`；分年读 `head_years`，分风格读 `head_regimes`；执行层读取 `ensemble.full_period/years/regimes`。实际数据适配以调研与测试样例确认。

### 3.4 分析

分析列表支持标题/标签搜索、日期与完成状态筛选；详情包括背景、方法、结论、代码使用说明、原始报告、代码文件及关联实验。

新分析可在页面新建、编辑、归档，保存到平台专属目录，不写生产数据或研究 registry。必填四个报告部分及至少一份代码文本/上传文件；支持多代码文件和导出报告/代码包。代码只展示和下载，不在平台中执行。归档可撤销，不提供不可恢复的直接删除。

首批只读导入现有 `backtest/diagnostics/*/REPORT.md`（目前发现三份），保留原文与来源；历史报告缺失代码或附件时显示「历史资料不完整」，不得补写成已验证可复现。用户可新建补充记录关联原报告，而不覆盖历史原文。

## 4. 数据与安全边界

- 研究源根明确配置为 `/Users/yuxianqi/Project/qlib_exp`；从其 registry 与被引用的 JSON 文件读取，禁止悄悄切到生产目录中的同名副本。
- 报告 HTML 是历史快照；registry 是记录入口，JSON 是指标源。展示源路径、修改时间、读取状态。文件更新后重载轻量索引，解析错误不能静默伪装成空记录；保留错误提示与其他可读条目。
- 原始报告和代码通过服务端批准的资源 ID 访问。路径需 `resolve` 后位于允许根内，阻止 `..`、绝对路径注入和符号链接越界。已清理的 result 目录标记「原产物已清理」，保留摘要。
- 原始 HTML 用受限 iframe 或附件方式呈现，不获得平台同源脚本权限。Markdown 禁用任意 HTML/脚本，代码按文本转义；展示路径不代表允许任意文件读取。
- 分析写入仅落在独立分析目录；采用原子写入、版本号冲突检测和写入锁，防止更新丢失。文件名、大小、文件数有限制，不允许可执行路径或服务器执行上传代码。
- 平台只监听 loopback；写 API 校验 Host/Origin、使用同源请求令牌，不启用跨域写入。分析目录不得与研究源、生产数据库或交易目录重叠。

## 5. 研发与上线隔离

实施在独立 checkout 中进行，使用当前已核对的提交作为基础。现有分支含未提交 QMT 剪贴板功能，与本任务无关，不搬动或覆盖。

禁止改动现有交易配置、调度、launchd、环境密钥、QMT 桥接目录、生产数据库，以及原监控静态资源。新进程启动不导入旧 `live_trading.web.api` 或旧应用工厂，不初始化 `LiveRecorder`/`MonitorStore`。

交付为可用的独立本地平台及启动说明。验证完成后可使用新入口；原服务保持原样，停止新增平台即可回退。安装常驻服务或替换旧入口不包含在本次默认动作中。

## 6. 验收

1. 原实盘三页功能全部可用，新平台的实盘故障不阻断研究与分析。
2. 四代模型和四代执行策略 baseline 均可追溯；代表性的全期、年度、风格值逐项核对原 JSON；单种子、running、延长窗和指定池记录正确分组。
3. baseline 列表、历史实验、筛选、同口径对比、报告入口、CSV 导出均可操作；缺失文件、空值、坏 JSON 有明确状态。
4. 新建分析保存后刷新仍存在；编辑冲突被检测；报告四部分与代码归档完整；历史缺失附件被标记；代码未执行。
5. 使用临时数据和模拟监控上游测试 GET 白名单、超时、路径越界、XSS、写入边界和比较口径；浏览器检查桌面与窄屏、导航竞态和错误状态。
6. 核对变更范围，确认无生产交易文件与进程变更。现有监控相关基线测试已执行：50 passed（2026-10-28）。

- 研究 registry 调研为 153 行，含四代模型 baseline 与四代执行层 baseline；HTML 可能滞后 registry。
- 现有分析报告明确记录过附件丢失；归档应如实呈现，不伪造代码或复现结果。
