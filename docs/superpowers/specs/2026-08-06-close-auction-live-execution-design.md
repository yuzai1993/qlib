# 收盘集合竞价实盘执行与持久化日志设计

## 背景与结论

当前 QMT 2.0.8.300（文件日期 2025-12-29）的内置文档仍将 `prType=49`
定义为“科创板盘后定价”。2026-08-05 模拟账户和 2026-08-06 真实账户均出现
`passorder` 无异常返回、但 QMT 未生成委托的相同行为。现有桥接程序又在调用返回后立即
写入 `ACCEPTED`，且只向 FormulaOutput 打印日志，导致客户端重启后缺少拒单证据。

实盘执行改为 A 股通用的收盘集合竞价限价单：14:57:05 使用 `prType=11`，买单显式
传入当日涨停价，卖单显式传入当日跌停价。最大股票仓位从 95% 降至 93%，每日保留
7% 现金，使 Top30/Drop2 的两笔新买入不依赖当日卖出回款。买卖均参与同一场收盘集合
竞价，实际成交价由交易所集合竞价产生。

## 目标与非目标

目标：

1. 对沪深 A 股使用 QMT 2.0.8.300 已支持的普通指定价委托。
2. 买卖尽量按收盘集合竞价价成交，保持与收盘价回测的可比性。
3. 区分“已调用下单 API”和“QMT 已创建委托”，消除假 `ACCEPTED`。
4. 将运行、下单参数、委托查询、成交和拒单回调持久化到 SMB 共享目录。
5. 保留真实账户、当日 `LIVE_OK`、100 股单笔上限和首次实盘账户预检。

非目标：

- 本次不解除 100 股上限，不进行全额实盘。
- 不再依赖 `prType=49`，也不等待客户经理确认后才完成一手测试准备。
- 不做盘中择时或根据集合竞价虚拟价格动态追价。
- 不通过提前卖出来获取资金。

## 执行协议

### 信号与配置

- 执行会话从 `AFTER_HOURS_FIXED_PRICE` 改为 `CLOSE_AUCTION`。
- 订单价格类型从 `AFTER_HOURS_CLOSE` 改为 `CLOSE_AUCTION_LIMIT`。
- QMT 报价类型固定为 `prType=11`。
- `submit_after` 为 `14:57:05`，终态确认从 15:00 后开始，账户快照在 15:01 后生成。
- 策略 `risk_degree` 从 `0.95` 改为 `0.93`；实盘对照回测配置同步修改，避免口径漂移。
- 单日新增买入仍最多为 2 只，单笔真实委托仍由 `MAX_ORDER_QUANTITY=100` 限制。

### 价格来源

QMT 通过 `ContextInfo.get_instrument_detail(stock_code)` 获取 `UpStopPrice` 和
`DownStopPrice`；为兼容旧客户端，同时支持旧名称 `get_instrumentdetail`。买单使用
`UpStopPrice`，卖单使用 `DownStopPrice`，并将所用价格、字段来源和合约信息写入日志。

以下任一条件不满足时，单笔订单不得调用 `passorder`，而是写入明确的 `ERROR` 回执：

- 合约详情不存在；
- 对应涨跌停价不是有限正数；
- 订单数量不是正的 100 股整数倍；
- 账户、环境、日期或安全开关校验失败。

### 现金储备与异常持仓

在 93% 最大仓位下，每只目标仓位约为总资产的 `93% / 30 = 3.1%`，两只买单约为
6.2%，7% 现金储备留下约 0.8% 缓冲。下单前仍按真实可用资金缩量，任何买单不得让
预计剩余现金低于安全缓冲。

若卖单因停牌、跌停无对手盘或其他原因未成交，而买单成交，账户可能暂时持有超过
30 只股票。次日计划必须优先处理遗留卖单；在持仓数大于 `topk`、存在未完成卖单，或
现金储备低于两只目标仓位需求时，禁止新增买单。该状态必须触发监控告警，但不得自动
重复提交已有 client order id。

## 委托状态与错误处理

`passorder` 是异步调用。调用未抛异常只表示请求已发出，不再生成 `ACCEPTED` 回执。

状态规则：

1. 调用前持久化 client order id，维持崩溃后不重复报单的 fail-safe 行为。
2. 调用后仅写共享日志中的 `SUBMITTED_UNCONFIRMED` 事件。
3. 只有 `get_trade_detail_data(..., "ORDER")` 查询到相同 `m_strRemark` 的委托，才写
   `ACCEPTED`，并保存 QMT 委托编号、委托状态、限价和错误字段。
4. 成交后按现有聚合逻辑写 `PARTIAL` 或 `FILLED`。
5. `orderError_callback` 捕获的拒单写为 `REJECTED`，保存错误文本和脱敏后的下单参数。
6. 15:00 后仍未查询到委托且没有错误回调时，写 `ERROR`，消息为
   `QMT order not observed after passorder`，不得再写普通 `EXPIRED`。

`init` 必须调用 `ContextInfo.set_account(ACCOUNT_ID)`，使账户级交易回调生效；绑定失败
时禁止真实下单。

## 共享目录日志

日志根目录为 `D:\qmt_bridge\logs`，每天至少生成：

- `qmt_bridge_YYYY-MM-DD.log`：便于人工阅读的时间戳文本日志；
- `qmt_events_YYYY-MM-DD.jsonl`：结构化事件，包括启动、账户绑定、批次认领、价格解析、
  API 调用、委托查询、成交、拒单回调、终结和账户快照。

每次写日志均使用追加模式，单次打开、写入、刷新并关闭文件，避免 QMT 崩溃或重启时
丢失缓冲区。日志写入失败不得令策略崩溃：回退到 `print`，并尽可能在后续轮询重试。
结构化日志不得记录密码、令牌或完整账户资产之外的敏感认证信息。

## 调度与恢复

- 定时器从 14:56:55 开始，每 3 秒轮询；14:57:05 首次允许提交。
- 14:57–15:00 不执行撤单，因为交易所收盘集合竞价阶段不接受撤单。
- 15:00 后轮询至 15:00:30，聚合最终委托和成交状态；15:01 写账户快照并归档批次。
- QMT 在提交后重启时，恢复逻辑先从 active state 读取 client order id，再查询当日委托；
  永不因为本地缺少 `ACCEPTED` 而重复下单。

## 测试与验收

自动测试必须覆盖：

1. 配置和信号 schema 仅接受收盘集合竞价协议及 `risk_degree=0.93`。
2. 14:57:05 前不下单，之后使用 `prType=11`；买入传涨停价、卖出传跌停价。
3. 新旧两个合约详情 API 名称均可使用，无效价格 fail closed。
4. `passorder` 返回后没有 QMT 委托时不写 `ACCEPTED`。
5. 查询到委托后才写 `ACCEPTED`，拒单回调写 `REJECTED`。
6. 共享文本和 JSONL 日志在模拟重启后保持可追加。
7. 缺少 `LIVE_OK`、账户绑定失败或真实账户预检失败时不调用下单 API。
8. 100 股上限保持生效；现金储备或遗留卖单不满足条件时禁止新增买单。
9. live_trading 全量测试、配置校验和实盘/回测 parity 检查通过。

Windows 验收继续只做真实账户一手测试。复制并编译新 QMT 源码后，先验证共享目录出现
启动和账户绑定日志，再创建当日 `LIVE_OK`。成功标准是 QMT UI 和结构化日志均出现真实
委托编号，数量不超过 100 股，委托限价与合约详情涨跌停价一致，最终成交价为收盘集合
竞价价，且监控、账户快照和完整性检查一致。
